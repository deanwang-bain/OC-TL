Bringing OpCat in-house after GLS

The goal is for Bain to own and run Opportunity Catalyst itself, with StatusNeo rolling off in stages so nothing breaks along the way. This paper sets out the three decisions that get us there, the options for each, and what each option leads to.

Recommendation

Split ownership between NGSS and BCN, hand over in three shadowed waves, and hire the lead engineer now

  • 1 · Who owns itOption C: NGSS runs engineering, BCN owns data and contentEach team does what it already does well.
  • 2 · How StatusNeo rolls offScenario 2: three waves with reverse shadowingStatusNeo fully off by mid-March 2027, with the riskiest work handed over last.
  • 3 · Who anchors itStart the Bain lead engineer hire nowEvery option depends on this role being in seat by early January.

If NGSS cannot take production engineering, use Option A, with BCN owning everything, and keep the same waves.

Decision 1 · Outcomes

What each ownership model looks like

Every option keeps Bain's product leadership, adds one new Bain lead engineer, and draws infrastructure from TSG / Andromeda, which already owns infrastructure and CI/CD by rule. Boxes are roles. Figures are full-time-equivalent estimates for running the product and do not include new feature work.

Option A

BCN owns build and run

What you get
One accountable team, closest to the OI domain. BCN already helped build the golden data set used at GLS.
What it costs
BCN takes on production engineering, release management and incident duty, which it does not do on OpCat today. Agent engineering is the furthest stretch from its current work.
Transition risk
high on agents medium elsewhere
Choose if
NGSS has no capacity from January, or keeping a single team matters most.
Option B

NGSS owns build and run

What you get
One engineering team, and probably the stronger run discipline. That second point needs confirming with NGSS.
What it costs
OI domain knowledge has to be rebuilt in a new team. BCN analysts are still needed for the golden data set, so in practice this is two teams, one of them informal.
Transition risk
medium high on domain and data
Choose if
NGSS has capacity and BCN cannot commit analysts.
RecommendedOption C

Split: NGSS engineers, BCN owns data and content

What you get
Each team does what it already does. BCN keeps the domain, the golden data set, content and data changes. NGSS takes code, releases and incidents. The data pipeline stays on the Bain side, where it already sits.
What it costs
Two teams means an interface to govern. A data fix that needs a code change crosses both, so the lead engineer has to hold them together.
Transition risk
medium
Why we recommend it
It puts each kind of work with the team best placed to keep it, and it is the easiest end state to grow into a permanent Bain capability.

A job description for this role has been drafted. It describes a hands-on engineer who owns the code through build and into live running.

What has to be true for a smooth transition

  1. The lead engineer is in seat before wave 1.
  2. A named Bain owner for the calculation engine and for the AI agents before anyone on StatusNeo's side of those leaves.
  3. The missing design standards (security, performance targets, monitoring, interfaces) are written before wave 2. A Bain team cannot run to a standard that does not exist.
  4. Staging loose ends are closed and the product moves off its proof-of-concept AI account before infrastructure goes to TSG.
  5. Open vendor and model approvals, including the web search provider, are settled before the agents move, so the Bain team does not inherit unapproved suppliers.
